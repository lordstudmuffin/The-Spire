# The Spire (prototype)

Godot 4.3+ project (tested on 4.3 and 4.7). Open `project.godot` in Godot (https://godotengine.org/download) and press F5.
First open imports the VRM models and animation clips (a minute or so).

## What's in the slice
- Main menu with New Game / Continue. Continue opens the **character select**: three save slots as cards (portrait drawn from the saved look, name, class, level, floor, playtime, last played) with Play / Edit look / Delete (inline confirm) per slot and New climber on an empty one. New Game takes the first free slot (or asks which to overwrite). The Online card shows which climber hosts/joins; Change picks another. Edit look reopens the creator in "Edit appearance" mode (cosmetics only; name, class and stats locked).
- Loading screen (`scripts/loading_screen.gd`, `LoadingScreen`): Spire key art, "Floor N · Name", a progress bar that advances between the world's build steps and rotating lore tips. Shown on Continue/New Game, on floor travel and while joining a server; the Floor 1 build is split into coroutine steps (`await LoadingScreen.step(...)` in `world.gd::_build_floor1`) so the window keeps painting. Headless runs (dedicated server, smoke test) and the screenshot harness build synchronously.
- Character creator: name, 4 starting classes, body (real anime VRM models Alicia / Godette / Seed-san, or the built-in Classic body with 7 hair styles), hair/eye/skin/outfit tints, height, 5 bonus stat points, live 3D preview.
- Characters: VRM models (the format VRoid Studio exports) rendered with the MToon cel shader, animated with CC0 KayKit clips retargeted to the humanoid rig (idle/walk/run/jump/hit/4 sword attacks). Drop more `.vrm` files in `assets/characters/` and register them in `VRMCharacter.BODIES`.
- Settings (title screen and pause menu): graphics preset Auto/Low/Medium/High/Ultra (Ultra targets RTX 4070/5070-class, Low runs on the Compatibility renderer), window mode, V-Sync, FOV, FPS counter (Graphics tab); volumes (Audio tab); mouse/stick sensitivity, deadzone, invert-Y, vibration and the remap list (Controls tab). Saved in `user://settings.json`. Presets also set a **foliage density** (Low 40 %, Medium 70 %, High/Ultra 100 % of grass/flower/undergrowth instances via `MultiMesh.visible_instance_count`, no rebuild) and a **small-prop cull distance** multiplier (Low 0.6, Medium 0.8, High 1.0, Ultra off: `GeometryInstance3D.visibility_range_end` on tiny/small prop batches and foliage chunks, fading over the last 12 %). See `RenderProfile.TABLE` (`foliage`, `prop_cull`).
- Floor 1 "Town of First Light": floating disc world, plaza with teleport gate, houses, fields, sealed Labyrinth tower.
- Third-person controller: WASD, mouse look, Shift sprint, Space jump, Q dash, left-click sword swing, middle-click target assist (camera swings to the nearest mob).
- **Gamepad** (Xbox layout, any pad SDL knows): left stick walks/runs by deflection, right stick orbits the camera (sensitivity, deadzone and invert-Y in Settings → Controls), A jump, B dash, X attack, Y interact, RB / LB / RT Sword Arts, LT target, L3 sprint, D-pad Inventory / Quests / Map / Party, View (Back) character sheet, Start pause, B backs out of any screen. Every menu is D-pad navigable with the shared cyan focus ring; key caps in hints turn into coloured button glyphs while a pad is in use (`InputSetup.input_device_changed`). Rumble on hits taken and heavy Sword Arts (`InputSetup.rumble`, toggle in Controls).
- **Remapping**: Settings → Controls lists every action with a keyboard/mouse column and a gamepad column; click one and press the new input (conflicts move off the other action), Reset to defaults restores `InputSetup.DEFAULTS`. Remaps persist as `bindings` in `user://settings.json` and are applied to the InputMap at startup (`Settings.apply_input`). `project.godot` carries a generated copy of the defaults so the editor's Input Map matches; `autoload/input_setup.gd` is the source of truth.
- Mobs: Field Boars (south) and Dire Wolves (north near tower). They wander, chase, hit back, drop XP and Col, respawn.
- XP curve, levels, 3 stat points per level (Tab opens the status menu), derived HP/attack/speed.
- Quest NPCs (E to talk): Guide Mira (5 boars), Captain Rhys (6 wolves), Elder Wren in Hollowbrook (ore delivery), Quartermaster Dain at Talven camp. Tower gate opens at level 5.
- Sword Arts on keys 1/2/3: Sweeping Edge (wide arc), Twin Crescent (heavy), Falcon Rush (lunge). Cooldowns shown on the bottom bar.
- Blacksmithing: mine Iron Ore from veins (E), hides/shards drop from mobs, talk to Smith Haldor by the plaza to forge. Every craft rolls a rank Normal..Myth. Equip gear from the Tab menu.
- Hidden class: craft 2 items and Haldor offers the Trial of the Forge; craft 5 to become Forgeborn. Two more are found, not offered: Stillblade (parry streaks, Dain at Talven) and Hearthwright (cook, fish and farm, then Rook). See docs/HIDDEN_CLASSES.md.
- Labyrinth: at level 5 the tower gate opens onto Terrace 1. Glowing pads climb to Terrace 2 (Kobold Scouts, a Kobold Sergeant) and then the summit arena.
- Floor Guardian: on the summit, Beat Gravelmaw (watch the ground slam) to clear Floor 1.
- Hollowbrook village (south-west) and the Talven camp (north-west) with their own NPCs.
- Toon (cel) shading with ink outlines; procedural world art (painterly ground, wind grass, trees, water, cottages, walled town, Labyrinth tower, cloud sea, floating islets) in `scripts/world_art.gd`.
- Saves: F5 quick save, Esc pause menu with Save / Save & Quit. Three JSON slots `user://save_0.json` .. `save_2.json` (slot 0 is the old single save, migrated in place; see `autoload/save_system.gd`). Each file is `GameState.to_dict()` plus `net_token` (per character) and `meta {format: 3, playtime, last_played, created, slot}`; playtime accumulates on every save from a session clock SaveSystem marks on load/new game. `SaveSystem.current_slot` is the slot in play: `save_game()` / `save_game(0)` write to it, so existing callers need no change.
- Performance: one-off Kenney/KayKit props placed through `AssetLib.prop` are not instanced but baked (deferred, end of frame) into one ArrayMesh per 24/48 m cell and size class, one surface per material (`AssetLib.flush_batches`); collision shapes are unchanged. Tiny props (< 1 m) drop their outline pass and shadows; tiny/small batches cull by distance. Grass, flowers and reeds are re-cut into 22 m chunk MultiMeshes (`WorldArt.chunk_foliage`) so they frustum-cull and honour the density/cull presets. Screenshot harness: `--stats [--stats-verbose]` prints mesh/multimesh/surface/shadow-caster counts (and per-family counts), `--preset Ultra` forces a preset for the shot, `--no-batch` restores the pre-batching structure for A/B comparisons.

## Floor 2 "Mirewood"
- Clear Floor 1 (beat Gravelmaw) and the sealed gate behind him sinks open: walk into the green light to ascend. Offline the same world scene reloads with `GameState.floor = 2`; the floor is saved with the character, so Continue returns you there. Respawn and "Return" pads use each floor's arrival point.
- A misty autumn floor: leaf litter and moss ground (`shaders/ground_mire.gdshader`, forest_floor / brown_mud_leaves PBR detail), fall-colour Nature Kit trees, mushrooms, drifting leaves and ground fog, a late-afternoon day/night palette (`DayNight.FLOOR_PALETTES`). Art in `scripts/world_floor2.gd` (Floor2Art); `scripts/world.gd` keeps the gameplay layer and picks `_build_floor1()` / `_build_floor2()`.
- Places: the arrival **Waygate** (Waykeeper Bran heals), **Thornwick** hunters' village west (Huntmaster Sable: hunt 6 Thornback Stags; Smith Orla's anvil), **the Mere** east with a lantern boardwalk out to the **Shrine of Still Water** (Keeper Ilsa: bring 5 Wisp Essence, learn the Drowned Plate recipe), the **Sunken Barrow** north-west (graveyard kit, wisps), and the second Labyrinth tower with one terrace (Thornback Alpha) and the summit arena.
- Mobs: Mire Toad (Lv 8, slow and tanky), Thornback Stag (Lv 10, fast charger, drops Stag Horn), Marsh Wisp (Lv 11, ranged bolt, drops Wisp Essence). Floor Guardian: **Mirelord, the Drowned Knight** (Lv 13): ground slam plus he raises two Drowned Wisps at the start and every 18 s (max four). Same server-authoritative hit rules as Floor 1.
- Recipes: Mirewood Blade (ore, stag horn, shard) and Drowned Plate (ore, hide, wisp essence; needs the shrine rite).
- Online: one server runs one floor. `godot --headless --path . -- --server --floor 2 --port 4490`. The server sends its floor during the join handshake (`{"floor": n}` via `send_auth`), the client sets `GameState.floor` from it and only then loads the world, so joining any server puts you on that server's floor. The Floor 1 summit gate online just explains that Floor 2 is a separate server.
- Screenshots: add `--floor 2` (and `--hour 21` for night) to the screenshot harness.

## Life layer (fishing, cooking, home)
- **Fishing**: stakes at the pond and the stream (Floor 1) and on the Mere's north shore and the shrine boardwalk (Floor 2). E with a Willow Rod casts; after a 2-5 s wait a bite shows the timing widget: press E while the marker is in the green. Fish: Minnow, River Trout, Mire Eel, Moonscale Koi (rarer fish = smaller zone, faster marker; tables in `LifeData.SPOTS`, skill shifts them toward koi). Fishing skill levels like smithing. Old Tam (pond) and Fisher Maud (Mere) give catch quests and lend a rod; Trader Pell sells one (40 Col) and Haldor forges one (recipe "Willow Rod").
- **Cooking**: the Talven camp fire, Thornwick's fire pit and your cottage hearth open the Cooking screen. Recipes: Grilled Trout (+2 HP/s), Boar Stew (+10% ATK), Eel Pie (+15% speed), Koi Sashimi (all three; Cooking Lv 3). Wild Herbs grow in clumps on the open grass (E to pick, regrow in 45 s). Food stacks under Provisions in the inventory; Use/Eat gives a timed buff shown bottom-left on the HUD.
- **Home**: the "For Sale" cottage on the east edge of Hollowbrook costs 300 Col (E twice at the door). Inside: hearth (cooking), bed (offline: sleep to 07:00 + Well Rested; online: the buff only), a storage chest (12 slots, moves gear out of the pack) and six furniture slots: E at a slot cycles through the decorations bought from Trader Pell (rug, bookshelf, fern, lantern, Gravelmaw trophy after clearing Floor 1). Ownership, furniture, storage, decorations, skills and buffs are saved offline; online they live on the server record.
- Online, every life action is a server request (see "What the server owns" under Multiplayer): the client only animates (the clump hides, the bobber drops, the widget runs) and the server books the ore / herb / fish / meal / purchase on the record and answers with a state patch. Screenshots: `--open fishing|cooking|home`.
- Code: `scripts/life/` (life_data, fishing, herb_field, home), `scripts/ui/` (fishing_widget, cooking_screen, shop_screen, storage_screen, life_hud).

## Multiplayer (early)
- From the main menu: **Host a floor server** (needs a saved character) or type an IP and **Join**. Default port 4433 (UDP).
- Dedicated server (no window): `godot --headless --path . -- --server --port 4433 [--floor 2]`
- Join handshake: the client connects, loads the world, then sends `{character, token, stats}`; the server sanitizes the character (name length, colors, height, origin) and checks the token, answers `{ok}` (the client completes auth only on that) and admits the peer, spawning them for everyone. A refused join answers `{reject: reason}` instead; the client stores it in `Net.last_error` and prints "Join refused: ...". The handshake allows 60 s (`Net.AUTH_TIMEOUT`) because a client builds its world before it sends its character and a cold load can take 10-20 s.
- Enter opens chat. Pause menu online only releases the mouse; the world keeps running.

### What the server owns (and what it still trusts)
Every state-changing action an online client takes is a request the server validates and runs on that character's record; the client never writes progress to the server. Pattern (`autoload/net.gd`): client `Net.request_action(kind, payload)` -> `net_request_action` (any_peer, rpc_id(1), self rate-limited) -> `Net._srv_action`: sender must hold a record, per-kind rate limit (`RATE_ACTION_MS`, e.g. craft 400 ms, cast 1.5 s, mine 700 ms; floods are dropped and logged), world checks in `world.srv_action` (range from `Player.srv_position()` to the vein / herb / fishing stake / camp fire / NPC / stall / cottage door, + 2.5 m slack; per-peer cooldowns on veins (30 s) and herbs (45 s); a landing needs a pending cast from the same spot that waited >= 2.4 s), then the *same gameplay code offline uses* (`Crafting.craft`, `LifeData.cook/eat/buy/rest/land_fish`, the world's quest talks, `GameState`-style methods) runs on a `RecordState` view of the record (`scripts/record_state.gd`) which checks materials, Col, levels, recipes, the rod, quest state and the pack size on the record. Success: record saved, `net_apply(kind, {patch, ...})` to the client, which adopts the patch with `GameState.apply_patch` (signals -> HUD, feed, quest log, buffs) and shows the toast / line; refusal: `net_apply(kind, {error})` and a server log line `[life] refused peer N (Name) kind {payload}: reason`. Offline and the listen-server host keep the local code path unchanged.

| Owned by the server (record) | How |
| --- | --- |
| Level, XP, stat points, stats | `srv_grant_reward` / `level_record` on kills and quest rewards; `spend_point` request; `unlock_hidden_class` adds the Forgeborn bonus on the record. |
| Col, materials, gear, equipped, `weapon_atk` | `craft` (rank rolled with the record's smithing level / class, item made on the server, pack cap 60), `equip` / `unequip` (by id from the record's inventory), `buy`, `buy_home`, `store` (chest cap 12), quest payouts; `weapon_atk` is derived from the equipped weapon, never reported. |
| Mining, herbs | `mine {vein}` / `herb {i}` against the world's own vein and herb positions, per-peer cooldown. |
| Fishing | `cast {spot}`: rod, range, fish rolled with the server's fishing level and `LifeData.SPOTS`; `land {spot}`: pending cast, wait, range; `land_fish` on the record (skill xp, catch quests). |
| Cooking, food buffs, rest | `cook` at a camp fire / fire pit / owned hearth; `eat` puts the buff on the record with an absolute expiry; `srv_attack_for` multiplies by the buff's ATK%; a 1 s server tick applies HP regen and expires buffs. `rest` in the owned cottage: full heal + Well Rested. |
| HP, death, respawn | `Player.take_damage` on the server routes a remote player to `Net.srv_damage`: armor soak, HP and death on the record; the owner gets `net_hp` (and hit feedback), a lethal hit heals the record and sends `net_apply "respawn"`. Falls never cost HP, so the client's own fall respawn needs no request. Party frames read HP from the record. |
| Quests | `talk {npc}` within talk range: the NPC's quest flow (`world._default_talk`, `_elder_talk`, `_keeper_talk`, `_fisher_talk`, `_smith_talk`, healers) runs on the record; gather quests mirror the record's materials. `enter_labyrinth` starts the Guardian quest; the floor clear reward (`floors_cleared`, boss quest, 3 shards) is written to every record on the summit in `_on_boss_died`. |
| Kill loot | `srv_reward_kill` rolls drops and quest credit for the killer on the server (`net_apply "loot"`); XP/Col split as before. |
| Cottage | `buy_home` at the door, `place {slot, id}` from owned decorations, `store`, `rest`; furniture and storage are record fields. |
| Mobs, hits, movement | Unchanged: mob AI/HP on the server, `Enemy.net_hit` range/facing/cooldown checks, `Player._server_movement_check` token buckets with kick after 6 corrections in 10 s. |

- **Snapshots** (`net_client_snapshot`, every 60 s / on save / on leave) adopt **nothing** any more: `srv_apply_snapshot` only audits the claim against the record (`[anticheat] peer N (Name) snapshot claims 99999 col (record 60), 50 moonscale_koi (record 0) ...; snapshot ignored, record kept`) and persists the record. `Player.net_report_stats` is likewise compared and logged once (`report ignored`).
- **Still client-trusted** (cosmetic or unverifiable): the character's looks (sanitized at join), the fishing minigame timing (whether E landed in the green zone; the server only knows a cast happened and enough time passed), swing/skill animations (`net_swing`, cosmetic), the client's own position between movement checks (validated, not simulated), the floor pads' teleports (accepted as safe destinations), and the client's local copy of XP/Col from the kill-share rpc (overwritten by the next patch / join). Nothing a client sends changes another player's record.

### Parties and social (server-authoritative)
- **Invite**: click a name in the chat log, press **O** (Nearby panel: everyone online with level / floor and Invite / Whisper buttons) or type `/invite Name`. The invitee gets a prompt under the player card (**Y** accept / **N** decline, or the buttons; invites expire after 30 s). Parties hold up to 6; the inviter leads; `/leave`, `/kick Name` (leader only); a party with one member left is disbanded and leadership passes to the oldest member when the leader leaves or disconnects.
- **Reward split** (`Net.party_split`, applied in `Net.srv_reward_kill` from `Enemy._die` on the server): a kill's XP and Col form a pool that grows **+10 % per extra member within 60 m** of the kill (server-accepted positions, same server), split evenly and floored (never 0 when the base was positive). 100 xp: solo 100, duo 55 each, trio 40, four 32. Each share is levelled on the server record (`srv_grant_reward`) and sent to that client with `Enemy.net_reward_split(xp, money, killer)`; **drops and quest credit stay with the killer**. Server log: `[party] kill by A shared with A, B: 13 xp / 2 col each (base 25/5, +10% bonus)`.
- **Party frames** (top-left under the player card, `scripts/ui/party_panel.gd`): level ring with the origin glyph, name, leader star, HP bar (red below 30 %) and distance (red beyond the 60 m share range). Fed by `Net.net_party_state`, a 0.5 s unreliable relay to party members only of `{peer, name, level, hp%, pos}`; HP is client-reported (`net_hp_report`, cosmetic only). Members get a green "PARTY" tag over their head and a green dot on the minimap (`Net.party_ids`).
- **Chat channels** (colours: say white, party cyan, whisper magenta, system gold): `/w Name msg` (server relays to the target only; you see `To Name: msg`), `/p msg` (party), `/who` (server lists name / level / floor / in-party), `/roll [N]` (to your party, else everyone), `/ignore Name` / `/unignore Name` (client-side mute, persisted as `ignored` in `user://settings.json`), `/help`.
- **Validation** (all in `autoload/net.gd`): every request rpc is `any_peer`, resolves its own sender, requires an admitted record (or the host), sanitizes names (16 chars, no control chars / brackets) and text (200 chars) and is rate-limited per peer: invite 1 / 2 s, party ops 2 / s, whisper and party chat 2 / s, `/who` 1 / 5 s, `/roll` 1 / 2 s, hp report ~3 / s. Targets must be online; party size, leader-only invite/kick and "already in a party" are enforced server-side; the server->client rpcs (`net_party_update`, `net_party_invited`, `net_party_state`, `net_chat`, `net_system`, `net_who_answer`) are `authority` and checked for sender 1. No XP ever comes from a client.
- **Harness**: `--bot --party` makes a bot `/who` every 6 s, invite the first other climber and auto-accept invites; two such bots pair up and hunt together (a party bot prefers mobs near its party members). Expect `[party] X joined party 1`, `[party] kill by ... shared with ...` and `[db] 'BotA'/'BotB' reached Lv 2` in the server log.

### Server-side persistence
- Any server (dedicated or host) keeps one JSON per character in `user://server_db/<sha256(lowercase name)[:24]>.json`:
  `{version, name, token, character, level, xp, money, stats, stat_points, materials, inventory, equipped, quests, smithing_level, smithing_xp, items_crafted, hidden_class, floors_cleared, weapon_atk, created, saved, last_peer}`.
- **Token**: a random 32-hex secret generated by the client on its first join and stored as `net_token` in that character's save slot (`user://save_N.json`; a new slot starts without one). The server creates the record with that token on first join and refuses later joins for that name with a different token ("The name 'X' belongs to another player on this server."). A name already online is refused too. Test clients (`--join --name X`) derive their token from the name so they can reconnect across runs; `--token <hex>` overrides.
- **On join** the server sends the record (minus token/HP) with `Net.net_adopt_snapshot`; the client runs `GameState.from_dict` on it (own looks kept, full heal). A first join on a server starts a fresh level-1 character for that name (creator stat points are accepted if they add up), independent of the offline save.
- **Snapshots**: the client still sends `GameState.to_dict()` every 60 s, on F5 / Save and on Leave (`Net.net_client_snapshot`, at most one per 20 s per peer, 64 KB max), but only as a "save now" ping: the server audits it against the record and ignores its contents. The server writes records on every accepted action, on level-up, every 60 s, on disconnect and on shutdown. Records on disk also carry `hp, recipes_unlocked, buffs (absolute expiry), fishing_*, cooking_*, fish_caught, home_*, decor_owned`; older files gain the fields on load (`Net.fill_record_defaults`).
- Online as a client, F5 / Save does not touch the offline slot: it refreshes the token in the file and asks the server to save.

### Test harness
- `--join <ip> --name Bot --bot --report` auto-creates a character, joins, walks to mobs, fights and prints state every 5 s.
- `--party` (with `--bot`) pairs bots into a party (see Parties above); run a server + `--name BotA --bot --party` + `--name BotB --bot --party`.
- `--quit-after <s>` leaves cleanly (snapshot + disconnect) after s seconds; `--token <hex>` forces a token (e.g. to see a refusal).
- `--cheat` (with `--bot`) teleports next to mobs, runs at 10x speed and claims level 99 / strength 99 / a 999-attack weapon, and 1.5 s after spawning fires forged requests: a snapshot with 99,999 Col, Lv 99, 50 koi and 50 Myth blades, `craft Spirit Blade` without materials, `land` a fish without a cast, `buy_home` with 50 Col, quest turn-ins (`talk` Elder Wren / Guide Mira) and `mine` / `herb` / `cook` / `buy` from across the island, `eat` food it does not have, `spend_point` with none, `equip` a forged id. Expected server log: `[anticheat] ... snapshot claims 99999 col (record 50) ...; snapshot ignored`, one `[life] refused peer N (Cheat) <kind> ...` per probe, `[anticheat] peer N (Cheat) claims Lv 99 ...`, `moved X m ... snapped back (k/6)` lines and `[anticheat] kicked peer N (Cheat): Impossible movement`, while the honest bot's lines keep coming.
- An honest `--bot` first walks a chore list (`world.gd` `CHORES`): mines two veins, forges an Iron Sword at Haldor's anvil, picks a herb, takes Old Tam's rod, casts and lands a fish at the pond, reports the ore to Elder Wren, then hunts. Expect `[bot] chore 'vein' done ... ore=3`, `[bot] chore 'fish' done: 1 catch(es)` on the client and no `[life] refused` lines for it on the server.

## Layout
- `autoload/` global singletons: input map, game state (stats/XP/gear/quests), save system, networking (Net), settings.
- `addons/vrm`, `addons/Godot-MToon-Shader`: VRM importer and MToon shader (MIT, V-Sekai).
- `assets/characters` placeholder VRM bodies (see CREDITS.md there; "Seed-san by VirtualCast, Inc.", VRM Public License 1.0), `assets/animations` KayKit clips (CC0), `assets/fonts` Nunito + Cinzel (OFL).
- `assets/audio` CC0 Kenney packs (impact, interface, UI, RPG, jingles) plus ambient/music loops; see `assets/audio/MANIFEST.md` and `assets/LICENSES.md`. `autoload/audio.gd` maps game events to them.
- `scripts/` scene scripts. Everything is built in code with primitive meshes so it works with zero art.
- `scenes/` thin .tscn files that just attach the scripts (`loading_screen.tscn` only exists for the harness; the game creates `LoadingScreen` in code).
